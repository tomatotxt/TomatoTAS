QUICK FACTS & ARCHITECTURAL DIRECTIVES

1. Project Philosophy & Core Scope

  - Direct State Overwrite ("Puppet"): The playback engine does not simulate
    hardware keystrokes or virtual movement vectors; it authoritatively
    overrides CFrame, AssemblyLinearVelocity, character geometry, and animation
    tracks on PreSimulation to eliminate physics divergence.
  - Pure Reference Legacy: FE2 TAS Creator V3.5 and TAS Player V5.6 are strictly
    architectural reference artifacts. Their file formats, closures, and logic
    flows can and should be redesigned into cleaner, more optimal
    implementations.
  - No Autofarm / Pre-Pass Phase: Recording is done directly through user
    control and savestates. Do not generate an automated bot/autofarm traversal
    phase.
  - Zero-UI Interface (Headless / Keybind-Driven): Do not write or depend on any
    UI libraries (e.g., uiapi.luau, Roact, ScreenGuis). All creator and playback
    interactions must be handled strictly via hotkeys (UserInputService /
    ContextActionService) to minimize overhead and focus 100% on engine
    mechanics.

2. Technical Directives & Map Mechanics

A. Dynamic Spawn Settle & Offset Resolution

  - The 1.0-Second Rule: In ~10% of maps, spawn platforms move at round start.
    The engine must sample the spawn platform on Heartbeat and verify position
    movement is static (\Delta \le 0.005\text{ studs}) continuously for a full
    1.0 second before recording initial offsets, creating savestates, or
    resetting the character.
  - Sub-Stud Accuracy: Spawn offsets must be calculated in local object space:
    \text{spawnOffsetCFrame} = \text{Spawn}_{\text{live}}.\text{CFrame}:\text{ToObjectSpace}(\text{Root}.\text{CFrame})
    Applied at playback via:
    \text{TargetCFrame} = \text{Spawn}_{\text{target}}.\text{CFrame} \times \text{spawnOffsetCFrame}
  - In-Game Verification: Ensure the character is out of the lobby lift
    (Vector3.new(-25, -144, 139)) by asserting
    \text{distance} > 300\text{ studs}, HumanoidRootPart.Anchored == false, and
    Humanoid.WalkSpeed >= 20.

B. Anti-Tamper & Clean Cloning

  - Connection-Stripper Fix: Neutralize FE2's Source 39 anti-tamper trap by
    using getconnections(inst:GetPropertyChangedSignal("Archivable")) to
    :Disable() / :Disconnect() all listeners before setting Archivable = true.
  - Sparse Table Bug Prevention: In the batch queue, never set table elements to
    nil while actively reading #Queue. Keep a dense, continuous array with a
    sliding pointer index (QueueIndex += 1) to prevent #Queue from prematurely
    evaluating to 0 in Luau.

C. Zipline Continuity (UpdRopeData)

  - Capture: When loading into the live map, listen to and cache the node array
    sent via Remote.UpdRopeData.
  - Injection: Cloned maps do not receive server network updates. After
    character reset/respawn in the cloned map, restore the cached RopeTable into
    FE2_Character's startZipline closure via upvalue injection:
    setupvalue(startZiplineFunction, 2, CachedRopeTable)

D. Branching TAS Architecture (Map Variants)

  - Some FE2 maps feature multiple routes, alternate puzzle paths, or random
    button variants.
  - The recording and savestate data model must support a Tree/Branching
    Structure (parent-child frame nodes) rather than a rigid flat array,
    allowing users to fork runs into distinct variant branches from any
    arbitrary frame.

E. Mechanics & Metamethod Spoofing

  - Slide Geometry: Sync HumanoidRootPart.Size and FE2_Hitbox.Size to (2, 1, 1),
    set Humanoid.HipHeight = -1.5, fire Animate.Sliding:Fire(true), and toggle
    SlideParticles.
  - Swing/Zipline State: Force
    Humanoid:ChangeState(Enum.HumanoidStateType.Physics) and fire
    Animate.Swinging:Fire(true).
  - MoveDirection Emulation: Hook __index on Humanoid.MoveDirection during
    playback to spoof targetVelocity.Unit so stock animation blend trees run
    naturally.
  - Anti-Cheat Neutralization: Disable Character.CL_AntiSideClip and
    Character.CL_AirMomentum.
  - Lift Unfreeze: Invoke Remote.RemoveWaiting:FireServer() post-respawn.

3. Phased Implementation Strategy

1.  Phase 1: Architecture, Type Definitions & Tree Model

5.  Phase 5: Puppet Playback Engine
